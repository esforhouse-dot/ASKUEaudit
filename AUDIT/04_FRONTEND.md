## Дизайн-система

Единая система токенов (CSS custom properties) во всех трёх/четырёх файлах: `--bg`, `--card`,
`--line`, `--tx`, `--accent`, брендовые `--brand-blue/sky/teal/lime` (из реального лого,
задокументированы в `CLAUDE.md`). Светлая/тёмная тема через `[data-theme]` + `prefers-color-scheme`
эквивалент — здесь конкретно через явный атрибут, сохраняемый в `localStorage('askue-theme')` и
применяемый inline-скриптом в `<head>` до рендера (анти-FOUC паттерн). «Швейцарская» типографика
(Archivo, без теней/скруглений, `border-radius:0 !important` как финальный слой) — введена
в сентябре 2026, согласно комментариям в коде, заменила более раннюю неоморфную систему.
CONFIRMED чтением `admin.html`/`login.html` целиком + структурных грепов `index.html`.

## Структура `index.html` (по секциям, из comment-маркеров)

Модем → Приборы учёта → АСКУЭ (графики/почасовка) → Тарифы → Объекты → Автоматизированные
отчёты → Регистратор → Входы/выходы, плюс сквозные JS-блоки: рендер графика сигнала/температуры
(инлайн SVG, без библиотек), генерация SMS-настроек, календарь выбора периода (click-click),
кастомные дропдауны категории/объекта, ползунок значений на графике (замена hover/tap),
вкладки (боковые на десктопе / выпадающее меню на мобильном), лимиты потребления, уведомления
и отклонения. CONFIRMED (структурные grep-маркеры `// ──` и `<!-- ──`).

Данные грузятся исключительно через `fetch()` к собственному `/api/*` — нет client-side роутинга,
нет SPA-фреймворка (React/Vue/etc.), состояние — в замыканиях/глобальных переменных модуля.
Графики — самописный inline SVG, без Chart.js/D3/etc. NOT FOUND — сторонних JS-библиотек
визуализации в проекте нет.

## Внешние ресурсы

Единственная внешняя зависимость на всех страницах — Google Fonts (`fonts.googleapis.com`,
шрифт Archivo), через `<link rel=preconnect>` + `<link rel=stylesheet>`. Никаких сторонних
скриптов (аналитика, CDN-библиотеки, виджеты) не подключается. CONFIRMED (grep по `<script src=`
и `<link` во всех HTML — единственные внешние hosts — fonts.googleapis.com/fonts.gstatic.com).

## XSS-защита

Единый паттерн: локальная функция `esc(s)` (HTML-escape `&<>"`) применяется перед вставкой
любого значения из API в `innerHTML`-шаблоны — 27 использований в `index.html`, 9 в `admin.html`,
1 в `login.html`. На сервере — зеркальный `sanitizeInlineHtml()` для текста лендинга,
редактируемого прямо в браузере (допускает только `<b>`, остальное вырезается до сохранения
в БД — двойная защита: очистка на входе + escape на выводе). CONFIRMED, KEEP AS IS.
Не найдено ни одного места, где значение с сервера подставлялось бы в `innerHTML` без `esc()`
среди проверенных фрагментов — полного построчного аудита всех 4733 строк `index.html` не
делалось (см. ограничения ниже), точечная выборка (админка, логин, структура) — чисто.

## CSRF

Явного CSRF-токена нет (NOT FOUND). Смягчающие факторы: cookie сессии — `HttpOnly; Secure;
SameSite=Lax` (см. [09_AUTH_AND_SECURITY.md](09_AUTH_AND_SECURITY.md)); все state-changing
запросы идут через `fetch()` с `Content-Type: application/json` — обычная HTML-форма
с чужого домена не может воспроизвести такой запрос без JS, а кросс-доменный `fetch` с
куки заблокирован browser same-origin policy (сервер не поднимает `cors` middleware для
`fetched/` — в отличие от старого приложения, где `cors` в зависимостях есть). Оценка риска
CSRF как низкого — INFERRED из этих фактов, не проверялось живым PoC-запросом (вне рамок
read-only аудита).
